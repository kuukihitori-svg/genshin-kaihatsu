# 纳塔分区开图 0.1.0 实验版

本版自动执行某橙sama [纳塔5.0开图 P2](https://www.bilibili.com/video/BV1xysNe1Ec4/?p=2) 中的 **3→4→5→6**：从已点亮的回声之子神像出发，开营地锚点、河谷锚点及万火之瓯神像。可以单独选择其中一段。

**目前不是全纳塔自动开图包。** 1→2→3的嵴锋龙与爬升、其余5.0区域、5.2、5.5、远古圣山及悠悠度假村的自动路线仍未实现。目录收录167处点位，其中159处为神像、锚点或秘境，8处为图腾柱等特殊设施；收录不表示有可执行路线。实际范围机器可读地列在 `coverage.json`。

适配“部分神像已亮、世界任务未做完”的使用方式：按分段运行，起点不可用时停下；营地剧情由玩家处理后接续。脚本不会把跳过的前置、模拟测试或编号进度条算作解锁证明。

## 安装与首次运行

1. 使用 BetterGI **0.66.0+**，更新纳塔地图资源，中文界面，小地图固定朝北，默认F交互键。实际游戏客户区需为16:9，1920×1080、2560×1440均可。
2. 把整个 `纳塔分区开图` 文件夹放入 `BetterGI\User\JsScript`，刷新JS脚本列表，添加至调度配置组。不要只复制 `main.js`。
3. 手动到已经点亮的**回声之子七天神像**，保持角色静止、停留游戏主界面。选择默认“仅原生定位自检”。报告保存在 `native-check.json`；自检不点击、传送或移动角色。
4. 默认定位连续稳定、与实际站位相符后，选择“执行已审阅路线”。首次可选“仅3→4”，满体力并保持普通角色形态；不要求闲云，也不自动使用角色技能或附身龙。3→4包含约40秒普通滑翔，需足够体力。
5. 如果触发营地剧情，脚本停止移动并等待，玩家手动处理当前对话。等待超时后处理剧情，重新运行同一组即可；脚本会重新核验已开点，再从当前未确认目标的起点执行。

若回声之子神像还没亮，请先按原攻略的1→2→3手动点亮。该前段有迷林之子前置和嵴锋龙爬升，小地图未揭示，首版没有输出猜测坐标。

## 原生能力与完成判定

- 传送：提瓦特调用 `genshin.tp(x, y)`；远古圣山调用 `genshin.tp(x, y, 'AncientSacredMountain', false)`。地图选点、图标校正和确认由原生流程处理，未加入固定像素偏移或额外地图面板OCR。
- 定位：`genshin.getPositionFromMap(mapName, 0)`；自检另比较原生SIFT与朝向。世界坐标重排为 **x=position[2]、y=position[0]**，高度单独保留，传送后对比的是 `tranPosition`。
- 导航：3个片段、73个来源点全部交给 `pathingScript.runFile()`，保留视频时间和坐标来源。导航返回后仍要核对目标位置；原生任务静默失败不能推进。
- 交互：仅在识别到唯一、居首的正确锚点或神像提示时按F。NPC或其他选项在上方时停止，不盲按。
- 解锁：**先实际到达同地图的远处核验起点，再原生传送至目标并连续检查落点**。这样角色站在锁定点附近、传送失败却返回时，不会被误记完成。二维落点过近、无法区分层高的点保留未知。
- 断点：`state.json`保存已核验目标、当前目标及片段，失败时保存截图和日志。旧断点只作记录，重新运行仍要取得当次核验证据，避免换账号或旧记录造成误跳过。

“仅原生传送测试”保持独立：只调用原生返回主界面和传送，不做脚本位置核验、OCR、导航或开图断点写入。

“核验分区已开点”会在所选分区逐点传送，输出 `unlock-report.json`；不按F、不替用户开启未开锚点。传送失败、定位失败或图层不明统一记为**未知**，不能解释为“未解锁”。已有完成记录在本次核验失败时撤销。

## 核验起点与地图

提瓦特默认使用入口锚点 `Teyvat:1170`，核验入口本身时改用回声之子神像 `Teyvat:1166`。请保证对应起点已经开放。远古圣山使用 `AncientSacredMountain:2` 与 `AncientSacredMountain:3`，必须先完成进入该独立地图的前置。

自定义核验起点可填写 `catalogue.json` 中自己已开的完整 `key`。它必须与目标属于同一地图、相距足够远；传送和落点检查仍然会实际执行。`1170`这类裸编号不足以标识点位。

| 点位键 | 本版用途 |
| --- | --- |
| `Teyvat:1170` | P2 1号入口，默认核验起点 |
| `Teyvat:1252` | P2 2号回声之子锚点，人工前段 |
| `Teyvat:1166` | P2 3号回声之子神像，自动路线起点 |
| `Teyvat:1172` | P2 4号营地锚点，可能触发剧情 |
| `Teyvat:1177` | P2 5号河谷锚点 |
| `Teyvat:1167` | P2 6号万火之瓯神像 |

**远古圣山是独立地图**，19个点使用 `AncientSacredMountain`，其余148个点使用 `Teyvat`。不得将独立地图坐标传给提瓦特定位或传送。地图内的地下层仍需另外确认，二维坐标不能证明高度正确。

## 已做的证据检查与待验收项

完整取得P2的1080p视频及音轨，顺序解码9,165帧；审阅62张全片采样帧，并细查起跳、落地、龙形态、剧情和末段台阶。用3个地图控制点拟合、另外3点交叉核对，最大残差约2.06像素；4,777帧得到地图或短时光流位置观测。音轨生成63段自动转写并对照画面核对机制；原始媒体、转写和截图留在研究工作区，不放入脚本包。

平台字幕轨需要登录，未取得；另对画面内教程、交互及剧情文字做3秒采样OCR和关键画面检查，**不能声称完成了逐条完整字幕验收**。`evidence.json`记录来源、时间戳、恢复方法与未知项。

- 4→5解说说明变龙用于加速，因此首版用普通步行沿原路线接近，不自动T/E附身；这一替代尚未实机验证。
- 5→6靠近未揭示区域后的小地图匹配不可靠，未采用后续低可信坐标。末个可靠点到已知神像约90个坐标单位，视频连续显示草地与浅台阶；原生跳跃接近该神像目标。**该末段需要首轮实机校准**，没有伪造插值点。
- 3→4普通滑翔、4→5步行替代、5→6河岸与台阶、实际剧情时序、交互OCR均需在原神/BetterGI中验收。当前没有实机通过记录。

## 开发与重建

仓库根目录运行：

```sh
npm run test:natlan
npm run build:natlan -- --zip dist/纳塔分区开图-0.1.0.zip
```

构建只使用提交的点位、导航证据和标准库，不联网。它拒绝混用地图、坐标轴错误、未知来源、缺少帧证据、无法解释的长距离连接和带未解决前置的可执行组。压缩包按文件白名单生成，不携带用户断点、自检、核验报告或运行日志。

坐标参考固定于 BetterGI [0.66.0 tp.json](https://github.com/babalae/better-genshin-impact/blob/0.66.0/BetterGenshinImpact/GameTask/AutoTrackPath/Assets/tp.json)，坐标轴依据 [GiWorldPosition.cs](https://github.com/babalae/better-genshin-impact/blob/0.66.0/BetterGenshinImpact/GameTask/AutoTrackPath/Model/GiWorldPosition.cs)，原生接口依据 [Genshin.cs](https://github.com/babalae/better-genshin-impact/blob/0.66.0/BetterGenshinImpact/Core/Script/Dependence/Genshin.cs)。目录覆盖是固定版本的静态快照，不代表对当前游戏所有新增点位进行了清点。
