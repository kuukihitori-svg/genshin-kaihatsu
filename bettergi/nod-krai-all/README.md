## 到达与解锁判据

传送调用原生 `genshin.tp(x,y,mapName,false)`，定位调用原生 `getPositionFromMap(mapName,0)`，移动调用原生 `pathingScript.runFile()`。原生函数返回后仍核验稳定坐标。步行约每28个坐标单位核验一次，连续滑翔和攀爬不在中途额外暂停；落地使用原生 `stop_flying`。

进入路线前要求距离源起点不超过35；每个片段结束要求距预期位置不超过6。若末端正确交互尚未出现，只有在目标12以内才允许一次原生近距接近。存在其他交互排在目标上方时不会按F。

交互后再次原生传送并核验传送落点，才写入 `state.json`。到达位置明显更接近另一个原生点时拒绝核验。该证据仍是原生传送结果与稳定二维位置，不声称有独立的高度／楼层识别；碰撞和楼层仍需实机验收。

断点文件不替代本次实际核验。失败保存日志和截图，取消异常继续抛给 BetterGI。导入包不包含账号日志、截图、断点或原视频。

- 月球三月灵入槽、浮空机关、护盾走廊、回收装置、计时任务和战斗。
- 努尔寂石阵列聚所5级供奉门槛的识别与所需资源流程。

这些条目保留在 `plan.json.gates` 中，不会因路过二维坐标而标记完成。BetterGI已核对的原生动作枚举中没有可直接替代上述月灵解谜的通用执行器；已复用的是传送、导航、方位点和下落攻击。
