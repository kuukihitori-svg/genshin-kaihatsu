# 伦波岛开图 P2：BetterGI 脚本实验版

按某橙sama [BV1XSHDzqE2h P2](https://www.bilibili.com/video/BV1XSHDzqE2h/?p=2) 的路线制作，覆盖 1—10 号中的锚点和秘境。针对本次账号状态：**伦波岛神像已点亮、相关剧情尚未完成**。1 号是自动开放的起点，3 号神像作为用户已确认的前提，其余目标支持执行和核验。

这是可导入运行的实验版，已做格式、宿主模拟和视频证据检查，**未在实际原神 / BetterGI 中跑通验收**。2 号街道途经点来自编号图人工量取，长距离滑翔的部分坐标由连续飞行区间插值得到，首次运行可能需要调整。

## 0.2.3：直接复用 BetterGI 原生地图传送

用户实机仍出现锚点点击偏下、打开标记面板，并在原生传送日志中出现 `_rowRange…m.rows` 图像区域越界异常。此前的小地图自检只证明原生接口在当前站位能连续返回一致读数，没有验证大地图选点。现有证据尚未确定偏移与越界发生的具体代码行，不能宣布已修复。

BetterGI 的地图传送已经包含所需功能。核对的0.66.0实现如下：

- [`Genshin.Tp`](https://github.com/babalae/better-genshin-impact/blob/0.66.0/BetterGenshinImpact/Core/Script/Dependence/Genshin.cs#L71)：JS `genshin.tp(x,y)` 直接等待 `new TpTask(token).Tp(x,y)`。
- [`TpTask.TpOnce`](https://github.com/babalae/better-genshin-impact/blob/0.66.0/BetterGenshinImpact/GameTask/AutoTrackPath/TpTask.cs#L406)：打开地图、切换区域与地表图层、准备点击视野、选点、确认传送、等待载入结束。
- [`ClickTeleportTargetMapPoint`](https://github.com/babalae/better-genshin-impact/blob/0.66.0/BetterGenshinImpact/GameTask/AutoTrackPath/TpTask.cs#L861)：使用 `TryGetAbsoluteTeleportClickPosition` 做图标位置校正；候选与传送按钮由原生流程识别。
- [`ClickMapPoint`](https://github.com/babalae/better-genshin-impact/blob/0.66.0/BetterGenshinImpact/GameTask/AutoTrackPath/TpTask.cs#L1308)：通用地图投影点击，不包含上述完整传送流程。

0.2.3移除本包通用地图点选及地图面板OCR核验，**地图选点、图标校正、候选选择和传送确认全部通过 `genshin.tp()` 复用同一套C#实现**。执行模式只在原生传送返回后补充实际到达位置检查；调用失败保留为“未知”，不能据此认定未解锁。尚未解锁的目标在预检时可能产生原生传送失败日志，然后才从对应起点接近并解锁。

账号已确认神像点亮，因此开图模式仍跳过神像点选和传送，不新增3号完成证明。若已经在1号起点20个坐标单位以内，取得连续稳定定位后直接沿1→2路线出发，避免重复传送；这不是解锁证明。屋顶、洞穴等其他起点仍实际传送，避免用二维坐标误判高度。

新增 **“仅原生传送测试”** 模式，可选择已确认开放的1号或3号点。此模式只记录版本/窗口信息并调用下面两行，不做脚本的地图点选、OCR、小地图位置核验或路线执行，也不写开图断点：

```js
await genshin.returnMainUi();
await genshin.tp(x, y);
```

测试目标的 `x/y` 来自 `plan.json` 原始传送点坐标。本版没有更改这些坐标，也没有添加固定像素偏移。如果此模式仍点击偏下或报图像越界，需查看 BetterGI 主日志中“传送异常”之前的DBG调用栈，才能定位原生流程的具体失败处。

本包是自定义脚本，以下功能由 BetterGI 内置实现执行：

- 定位：`genshin.getPositionFromMap('Teyvat', 0)`，沿用 BetterGI 的地图匹配设置。
- 朝向读取：`genshin.getCameraOrientation()`。
- 转向：`pathingScript.run()` 中的 `type: "orientation"` 方位点，实际调用 BetterGI 的 `FaceTo` / `CameraRotateTask`。已移除本包手写的鼠标转向控制器。
- 导航：所有12段路线都交给 `pathingScript.runFile()`；山谷段也使用原生导航，仍保留片段结束的位置核验与一次剧情恢复。
- 传送和解锁核验：`genshin.tp(x, y)`，执行模式另核对实际到达位置；不再使用通用地图点选或地图面板OCR。

定位接口在前一版已使用；本次新增可单独运行的原生自检，并替换剩余的手写转向与山谷导航。升降台出口、洞口末段仍有最长4秒、可取消的短距离按键接近，需识别对应交互才会确认到达。

原生接口与路径格式见 [JS 接口](https://www.bettergi.com/dev/js/genshin.html)、[方位点格式](https://www.bettergi.com/dev/pathing-dev.html)及核对过的 [0.66.0 PathExecutor](https://github.com/babalae/better-genshin-impact/blob/0.66.0/BetterGenshinImpact/GameTask/AutoPathing/PathExecutor.cs)。[BetterGI 脚本仓库示例](https://github.com/babalae/bettergi-scripts-list/blob/f1981a034d85015574e6352fb0fc71f0f8fcb324/repo/js/IceObjectNpcLike/src/modules/pathing.js)同样使用 `orientation` 和原生小地图坐标；本包没有复制该示例的任务逻辑。

## 先运行原生自检

升级时完整覆盖本文件夹内同名脚本文件并刷新 BetterGI 列表；保留已有 `state.json` 与 `logs`。启动日志必须显示 **0.2.3-experimental**。

1. 手动回到游戏主界面，保持角色静止，小地图方向固定朝北。
2. 在脚本配置中选择默认的 **“仅原生定位自检”**，运行一次。
3. 自检读取4组原生坐标和朝向，对比默认匹配与原生 `getPositionFromMapWithMatchingMethod('Teyvat', 'SIFT', 0)`。此模式不发送按键、点击、传送或路线任务，也不写开图断点。
4. 查看 BetterGI 日志的“原生自检结果”，完整结果在脚本文件夹的 `native-check.json`。若只有 SIFT 连续稳定，在 BetterGI 地图追踪设置中选择 SIFT 后重测；自检不会修改全局配置。该设置也影响原生传送。
5. 默认定位连续稳定、朝向可读取，且位置与实际站位相符后，再选择 **“执行开图路线”**。两种匹配坐标若不一致，先核对地图资源和实际站位。

若小地图自检已通过但大地图仍点偏，选择“仅原生传送测试”，目标选“1”，查看 BetterGI 主日志。测试不会执行开图，结果不代表路线或交互通过验收。

“连续稳定”只代表多次读取一致，不能单独证明绝对坐标准确、图标点击成功或路线可通行。自检不选神像，因此可以在当前可识别位置运行；它不会验证大地图点击功能。

**2560×1440 本身是标准16:9**。脚本读取 BetterGI 实际检测的 `genshin.width/height`，记录识别截图尺寸和系统 DPI；非16:9客户区会在操作前明确停止。录屏编码尺寸不能代替客户区尺寸。先前独立地图对齐确认了目标世界坐标，但现有证据未确定选点偏移的底层原因，仍需实机复测。

## 安装与运行

1. 使用 BetterGI **0.66.0 或更新版本**，确认地图资源覆盖挪德卡莱、小地图方向固定朝北，实际游戏客户区为16:9。
2. 将整个文件夹复制到 `BetterGI\User\JsScript\伦波岛开图P2`。不要只复制 `main.js`；需同时包含 `plan.json` 和 `routes`。
3. 在 BetterGI 刷新 JS 脚本列表，选择“伦波岛开图 P2（视频路线实验版）”，添加到调度配置组。
4. 首次先运行“仅原生定位自检”。执行开图时选择“执行开图路线”和执行范围。“2—10”为完整范围；也可选择“仅6→7”，这要求6号起点已开。角色须具备普通滑翔能力和足够体力；使用中文游戏界面、默认 F/T/空格交互键，关闭其他抢占输入的宏。
5. 开始运行。脚本核对当前位置后，从所选路段开始；不再强制传送神像。能直接传送到的既有目标会重新核验后跳过。

无需登录 B站、安装 Python、联网请求视频或在 Windows 上运行研究工具。脚本只调用本地 BetterGI 接口。

## 实际执行流程

- **2 号**：到达1号起点后按街道与台阶路线前往2号；已稳定站在1号附近时复用当前站位。录像中小地图是黑图，该段中间点来自开头编号图，标为近似坐标；观景点属于可选内容，不主动交互。
- **3 号**：沿用用户已确认点亮的前提，跳过选点和传送，不新增核验成功记录，不重放原录的绕行。
- **4 号**：返回 2 号，沿商店右侧接近升降台；识别“上行”，分两次升到最上层，再向锚点出口移动。
- **5 号**：从 4 号高处起飞，经过草地后走到崖边；最后短距离下落只在识别到正确锚点提示后按 F。洞口小地图可能暂时无法定位，此处不会长时间盲走。
- **6 号**：原生地图追踪沿山谷北行，十字路口左转，使用原录中的 T（空月之灵）与攀升路线。该段启用 AutoSkip；原生导航结束后若未取得预期位置，等待主界面稳定恢复，再返回5号重走，最多恢复一次。原生导航中的输入和异常处理由 BetterGI 负责。等待超时会停止，日志提示处理剧情后从“仅5→6”续跑。
- **7 号**：返回 6 号，沿道路前往起重设备平台。
- **8 号**：从 7 号高处滑翔至工坊前。412—430 秒没有可靠绝对定位，因此这部分使用已检查连续性的飞行插值点；需实机检查体力、峡谷碰撞与降落位置。
- **9 号**：开完 8 号后，实际传回 **7 号**，再从高处滑翔至无光的深都。不是从低处 8 号直接飞。
- **10 号**：返回 **6 号**，上坡后从崖边滑翔下降。

## 完成判据、停止和恢复

`pathingScript.runFile()` 返回后还会检查实际地图位置。方位点结束后检查朝向与站位，再允许短距离前进。即使宿主只记录异常而不抛错，也不会直接记为成功。

交互只接受目标对应的“传送锚点”或“无光的深都”提示；有其他可读交互排在上面时，不直接按F。解锁证据是原生传送成功并在目标附近取得稳定定位。标记编辑器、路过目标、复用起点和按过F均不作为成功依据。原生传送异常会保留其日志并停止完成核验，不会反复尝试不同像素偏移。

失败时释放本脚本按下的移动键，记录 `state.json`，保存 `logs` 下的截图与逐行日志，并向 BetterGI 抛出错误。不会无限尝试、自动挑战秘境或自动消耗树脂。单独的剧情 AutoSkip 仅在 5→6 段运行，结束或出错时清理。

执行模式再次运行会通过原生传送重新核验目标，确认已开后可以跳过对应开图路段；断点文件本身不证明目标已开。也可以在配置中选择从4号、6号或指定小段开始。日志和原生自检报告只保存在本地，不会上传到外部服务，也不会进入构建包。

## 证据与验证范围

原视频 1920×1080、30fps；全片 **15,612 帧**已顺序解码，使用 SIFT/RANSAC 绝对匹配与相邻帧光流做定位，取得 7,544 帧的位置估计。路线连续性联系表、关键操作原帧与自动转写做了交叉核对；不声称人工逐一看完全部 15,612 帧。

12 个路线片段共 159 个途经/目标点。每个点的时间、来源类型及匹配数量保留在 `plan.json`；原生路线 JSON 在 `routes`。`guide-map` 为编号图人工点，`continuous-flight` 为连续滑翔插值，`sift` 为地图匹配，`source-tp` 为公开传送点坐标。所有点仍需实机验证三维通行性。

坐标按 BetterGI `GiWorldPosition` 转换：路线 X=原始 `position[2]`，Y=`position[0]`。原视频 SHA-256、逐帧分析范围与假设保留在 `plan.json.source`。

已验证29组宿主模拟/结构检查，涵盖导航与转向静默失败不能推进、非目标提示不按F、严格的解锁证据、剧情恢复、取消释放按键、两次上行、回程传送、2560×1440归一化截图、非16:9客户区提前停止、原生地图传送入口、无通用地图点选、自检无游戏输入、原生传送独立测试保留错误、起点复用不作为完成证明。宿主模拟无法验证游戏碰撞、实际OCR准确率、原生定位精度和窗口兼容性。
