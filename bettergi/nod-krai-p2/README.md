# 伦波岛开图 P2：BetterGI 脚本实验版

按某橙sama [BV1XSHDzqE2h P2](https://www.bilibili.com/video/BV1XSHDzqE2h/?p=2) 的路线制作，覆盖 1—10 号中的锚点和秘境。针对本次账号状态：**伦波岛神像已点亮、相关剧情尚未完成**。1 号是自动开放的起点，3 号神像做已解锁核验，其余目标支持执行和核验。

这是可导入运行的实验版，已做格式、宿主模拟和视频证据检查，**未在实际原神 / BetterGI 中跑通验收**。2 号街道途经点来自编号图人工量取，长距离滑翔的部分坐标由连续飞行区间插值得到，首次运行可能需要调整。

## 0.2.1：神像选点与窗口核验修复

实机录屏中，旧版通用地图点击落在神像下方，打开“标记”编辑器，然后错误地报告神像未点亮。**2560×1440 本身是标准16:9**，不能将此失败直接归因于分辨率比例；录屏编码尺寸也不等于游戏客户区尺寸。独立地图图像对齐确认了目标世界坐标，屏幕选点是本次直接失败点；现有证据未确定 Windows DPI 等更底层偏移因素。

0.2.1 启动时读取 BetterGI 实际检测的 `genshin.width/height`，记录识别截图尺寸和系统 DPI，非16:9客户区会在操作前明确停止。1920×1080、2560×1440均接受，不要求一律改成1080p。

神像预检改为原生 `genshin.tp(x,y)` 加到达位置核验，使用原生传送流程中的图标校正，不再用通用 `clickMapPoint` 检查神像。普通目标若点开标记面板或未读到完整详情，会保留为“未知”，并尝试原生传送核验；实际到达也可作为解锁证据。无法核验不再等同于未解锁。

升级时完整覆盖本文件夹内同名脚本文件并刷新 BetterGI 列表；保留已有 `state.json` 与 `logs`。启动会先实际传送到伦波岛神像一次，再按执行范围前往路线起点。修复经过1920×1080、2560×1440／150% DPI等宿主模拟回归，尚待用户电脑实机复测。

## 安装与运行

1. 使用 BetterGI **0.66.0 或更新版本**，确认地图资源覆盖挪德卡莱、小地图方向固定朝北，实际游戏客户区为16:9。
2. 将整个文件夹复制到 `BetterGI\User\JsScript\伦波岛开图P2`。不要只复制 `main.js`；需同时包含 `plan.json` 和 `routes`。
3. 在 BetterGI 刷新 JS 脚本列表，选择“伦波岛开图 P2（视频路线实验版）”，添加到调度配置组。
4. 选择执行范围。“2—10”为完整范围；首次也可以选择“仅6→7”检查地图定位与交互。角色须具备普通滑翔能力和足够体力；使用中文游戏界面、默认 F/T/空格交互键，关闭其他抢占输入的宏。
5. 开始运行。脚本先核验伦波岛神像可传送；能直接传送到的既有目标会重新核验后跳过。

无需登录 B站、安装 Python、联网请求视频或在 Windows 上运行研究工具。脚本只调用本地 BetterGI 接口。

## 实际执行流程

- **2 号**：传送 1 号，按街道与台阶路线前往 2 号。录像中小地图是黑图，该段中间点来自开头编号图，标为近似坐标；观景点属于可选内容，不主动交互。
- **3 号**：核验已经点亮的神像，不重放原录的升降台与空月之灵绕行。
- **4 号**：返回 2 号，沿商店右侧接近升降台；识别“上行”，分两次升到最上层，再向锚点出口移动。
- **5 号**：从 4 号高处起飞，经过草地后走到崖边；最后短距离下落只在识别到正确锚点提示后按 F。洞口小地图可能暂时无法定位，此处不会长时间盲走。
- **6 号**：沿山谷北行，十字路口左转，使用原录中的 T（空月之灵）与攀升路线。进入剧情时释放移动键，启用 AutoSkip 等待主界面稳定恢复，再返回 5 号重走；最多恢复一次。等待超时会停止，日志提示处理剧情后从“仅5→6”续跑。
- **7 号**：返回 6 号，沿道路前往起重设备平台。
- **8 号**：从 7 号高处滑翔至工坊前。412—430 秒没有可靠绝对定位，因此这部分使用已检查连续性的飞行插值点；需实机检查体力、峡谷碰撞与降落位置。
- **9 号**：开完 8 号后，实际传回 **7 号**，再从高处滑翔至无光的深都。不是从低处 8 号直接飞。
- **10 号**：返回 **6 号**，上坡后从崖边滑翔下降。

## 完成判据、停止和恢复

`pathingScript.runFile()` 返回后还会检查实际地图位置。即使宿主只记录导航异常而不抛错，也不会直接记为成功。

交互只接受目标对应的“传送锚点”或“无光的深都”提示；有其他可读交互排在上面时，不直接按 F。解锁证据是正确目标地图面板中 OCR **完全等于“传送”**的按钮，或图标感知的原生传送成功并在目标附近取得稳定定位。标记编辑器、路过目标和按过 F 均不作为成功依据。

失败时释放本脚本按下的移动键，记录 `state.json`，保存 `logs` 下的截图与逐行日志，并向 BetterGI 抛出错误。不会无限尝试、自动挑战秘境或自动消耗树脂。单独的剧情 AutoSkip 仅在 5→6 段运行，结束或出错时清理。

再次运行会重新检查地图状态，已开目标可以跳过；断点文件本身不证明目标已开。也可以在配置中选择从 4 号、6 号或指定小段开始。日志用于修正首轮未通过的站位、镜头或路线，不会上传到外部服务。

## 证据与验证范围

原视频 1920×1080、30fps；全片 **15,612 帧**已顺序解码，使用 SIFT/RANSAC 绝对匹配与相邻帧光流做定位，取得 7,544 帧的位置估计。路线连续性联系表、关键操作原帧与自动转写做了交叉核对；不声称人工逐一看完全部 15,612 帧。

12 个路线片段共 159 个途经/目标点。每个点的时间、来源类型及匹配数量保留在 `plan.json`；原生路线 JSON 在 `routes`。`guide-map` 为编号图人工点，`continuous-flight` 为连续滑翔插值，`sift` 为地图匹配，`source-tp` 为公开传送点坐标。所有点仍需实机验证三维通行性。

坐标按 BetterGI `GiWorldPosition` 转换：路线 X=原始 `position[2]`，Y=`position[0]`。原视频 SHA-256、逐帧分析范围与假设保留在 `plan.json.source`。

已验证：脚本语法、路线结构、导航静默失败不能推进、非目标提示不按 F、严格的解锁证据、剧情恢复、取消释放按键、两次上行、回程传送、2560×1440归一化截图、非16:9客户区提前停止、标记面板不误判为锁定、原生传送到错位置不记成功。宿主模拟无法验证游戏碰撞、实际 OCR 准确率和 BetterGI 窗口兼容性。
