尚未在真实原神／BetterGI 中跑通。特别是 **1→2 仍为人工量图，5→6 是未实测的斜坡步行变体**，不能当作已验收路线。全挪德卡莱工程另见[分区开发包](../nod-krai-all/README.md)。

## 本次变化

- 重新用 BetterGI 原生1024地图的坐标原点恢复11段路线，共12段、246个途经点。7→8不再使用飞行插值；1→2保留近似标记。
- 步行段约每28个坐标单位分段核验位置，起点相差超过35会停止。连续滑翔和攀爬保持连续，避免额外停顿改变高度。
- 取消斜坡处盲按T和空格，改为沿连续斜坡步行；该变体仍待实测。
- 升降台每次上行后须识别“升降机已启动”，第一段结束后等“上行”重新出现，再启动第二段。最后仍须实际出现锚点交互并通过原生传送核验，等待时间不作为楼层证明。
- 滑翔降落复用 BetterGI 原生 `stop_flying` 下落攻击处理，避免仅凭二维坐标认定已经落地。

地图选择、图标校正、候选选择、确认及加载全部调用 [genshin.tp / TpTask](https://github.com/babalae/better-genshin-impact/blob/0.66.0/BetterGenshinImpact/GameTask/AutoTrackPath/TpTask.cs)，没有自写地图点选或像素偏移补偿。移动调用原生 `pathingScript.runFile()`，方位调整调用原生 `orientation` 点。

## 导入与运行

1. 使用 BetterGI 0.66.0 或更新版本，把ZIP解压出的“伦波岛开图P2”文件夹放入 `User/JsScript`；`manifest.json` 和 `main.js` 应在同一层。
2. 刷新脚本列表，加入调度配置组。游戏客户区须为16:9，2560×1440可用；使用中文界面和默认交互键。
3. 默认“仅原生定位自检”不会移动。已确认传送正常后可选“执行开图路线”；本次斜坡修正可用“仅5→6”单独测试，要求5号已开。
4. 其他范围保留“仅4号”“仅6→7”“4—10”“6—10”等；各范围的起点须可传送。无需在Windows上安装视频研究工具。

3号神像沿用账号已点亮的前提，不新增脚本完成证明。4号从2号乘两段升降台；5号从4号高处下降；6号从5号沿山谷左转上斜坡；7号沿路；8号从7号滑翔；9号重新传回7号前往秘境；10号重新传回6号后下降。

5→6启用原生 AutoSkip；剧情打断定位时等待主界面稳定，返回5号恢复一次，超时停止。断点文件不替代本次实际核验。

## 验证和限制

原录15,612帧已全帧顺序解码，本次取得8,282帧位置估计。坐标来自原生地图 SIFT/RANSAC、最长1秒的光流衔接，以及强匹配后3秒内受尺度和速度约束的局部匹配。关键原帧、联系表与自动语音转写交叉核对；**没有人工逐一审看全部帧、逐句亲耳听完或完整审完所有字幕的声明**。

`plan.json` 保留视频哈希、时间、帧号和来源。原生地图坐标为 `(16384-pixelX,12288-pixelY)`；传送点转换为路线X=`position[2]`、Y=`position[0]`。

30项宿主模拟检查覆盖静默导航失败、原生传送失败、非目标交互、两次上行和启动提示、剧情恢复、取消释放按键、2560×1440与150% DPI、自检及起点复用。宿主模拟不验证游戏碰撞、实际OCR、三维高度或真实运行成功。

失败时停止、保存 `state.json`、`logs` 下的截图与日志。完成记录只在原生传送返回且目标附近定位稳定后写入。日志、自检与断点留在本地，构建ZIP不包含它们。
